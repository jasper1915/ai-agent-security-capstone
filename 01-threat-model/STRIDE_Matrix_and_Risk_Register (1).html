F3 Human User → AI Agent (Chat / Access Token) Attacker session hijack (stolen cookie) Modify prompt in transit (MITM if TLS broken) User denies sending jailbreak prompt PII in chat captured by third-party plugin Prompt flood / token exhaustion User claims elevated role in prompt (role injection)
F4 AI Agent → Human User (OAuth Claims Response) Response spoofed by compromised agent instance Response content altered before rendering No log of what claims were shown to user Agent exposes internal system prompt in reply Large repeated responses exhaust client resources Agent grants itself broader claims than authorized
F5 AI Agent → RAG Pipeline (RAG Query) Rogue service impersonates AI Agent identity Inject / alter query embeddings Retrievals not logged with chunk IDs Sensitive runbooks retrieved into context Retrieval storms / vector DB saturation Query filter bypass returns restricted tenant data
F6 RAG Pipeline → AI Agent (Retrieved Context/Chunks) Poisoned pipeline identity injects fake chunks Chunk poisoning (embedding manipulation) No trace of which document a chunk originated from Chunk includes embedded secrets/credentials Oversized chunk payloads degrade agent performance Malicious chunk grants agent unintended authority
F7 AI Agent → Internal REST API (OAuth Token + Request) Spoofed agent JWT accepted (wrong JWKS) Tamper request body after authentication API logs lack agent_id / user_sub binding Excessive customer PII returned in response model High-rate ticket / request export abuse IDOR / scope confusion (confused deputy)
F8 Internal REST API → AI Agent (API Response) Fake API response injected via MITM Response payload manipulated in transit No correlation ID linking response to request API returns more fields than agent needs (over-fetch) API rate-limits agent, degrading service to user Agent trusts response to self-elevate permissions
F9 AI Agent → MCP Client (Tool Request) Fake MCP peer / tool name spoofing Tool-argument injection / schema abuse Tool calls without signed audit entry Tool returns secrets into LLM context Recursive tool-call loop causes DoS Unallowlisted tool invoked with admin side effects
F10 MCP Client → Knowledge Base (Retrieval Request) Client identity spoofed to KB service Retrieval request parameters altered No log of which KB records were accessed Knowledge Base returns restricted/internal docs Bulk retrieval requests exhaust KB throughput Client granted read access beyond assigned scope
F11 MCP Client → MCP Server (Protocol Request) Rogue MCP server impersonation (no mTLS) Protocol message tampering (unsigned payload) Server accepts calls without signed operator identity Server discloses internal tool metadata/config Malformed protocol requests crash MCP server Client invokes privileged/admin-only server tools
F12 MCP Server → MCP Client (Tool Result / Resource) Result spoofed by compromised server process Result payload altered before return Identity Audit Log missing entries for tool results Result includes raw secrets / credential material Oversized results overload client memory Result triggers unintended privileged action downstream
F13 AI Agent → Secrets/Credentials Store (Cred Request) Workload identity spoofed at credential checkout Secret swapped with attacker-controlled value Credential checkout not attributable to a specific run Long-lived key logged in plaintext / sidecar Lockout from repeated bad checkout attempts Agent obtains broader-scope credential than needed
F14 Internal REST API → LLM Provider (LLM Response path) Federated LLM provider identity impersonation Response tampering in provider relay path No SIEM correlation of provider call events Provider call leaks prompt/context data externally Provider outage blocks all downstream agents Provider response used to escalate agent role
